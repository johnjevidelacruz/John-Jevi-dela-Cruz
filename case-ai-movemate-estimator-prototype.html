Case study

MoveMate AI Estimator: Prototype for Faster Move Scoping

Estimating breaks when item lists are incomplete or inconsistent. The prototype explored an AI-assisted flow to identify items and standardize scope for quoting.

← Back to case studies

At a glance

  • Role: Product/ops prototyping
  • Stack: LLM-based item classification (prototype), workflow design
  • Deliverables: Scope definition, estimation flow, next-step roadmap

Key highlights

  • Structured item taxonomy for quoting
  • Human-in-the-loop estimation workflow
  • Roadmap for data collection + integration

Context

Designed an MVP estimator concept for moving operations to improve quoting consistency and reduce back-and-forth with customers.

Objective

Capture the minimum info needed for a usable estimate and make that data flow into CRM + scheduling cleanly.

Approach

I mapped the data model first, then the user flow, then the operational outputs.

  • Defined required fields (move date, addresses, inventory, access notes, time windows).
  • Designed rules for common pricing drivers (stairs, long carry, bulky items).
  • Specified outputs: estimate summary, internal notes, and CRM field mapping.
  • Outlined the next technical steps for automation and validation.

Deliverables

A practical MVP spec.

  • Field list + definitions + validation rules.
  • Output format for sales and ops handoff.
  • CRM mapping notes for consistent downstream reporting.

Results

Reduced ambiguity in what “good intake” looks like and created a clear roadmap for building the estimator without scope creep.

Reusable checklist

If you’re doing something similar, this is the short checklist I follow to keep the work clean and close-ready.

  • Start with required fields and validation; don’t build fancy UI first.
  • Define the output that ops needs (not just what sales wants to show).
  • Map each field to CRM so reporting stays clean.
  • Design exception handling (unknown inventory, ambiguous access) upfront.
