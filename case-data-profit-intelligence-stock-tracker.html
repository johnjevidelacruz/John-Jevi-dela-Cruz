Case study

DTC Ecommerce: Profit Intelligence + Inventory/Stock Tracker

This system was built to answer practical questions every day: ‘Did we actually profit yesterday?’, ‘What’s our true CAC/ROAS?’, and ‘When do we reorder before we stock out?’

← Back to case studies

At a glance

  • Role: Data + automation builder
  • Stack: CheckoutChamp, Facebook Ads, Google Sheets, Zapier
  • Deliverables: Multi-tab model, automations, QA checks, dashboards

Key highlights

  • Unified profit + inventory dashboards
  • Fixed missing orders via API source correction
  • FIFO-style costing and QA checks

Context

Designed and implemented an end-to-end Profit Intelligence + Inventory Tracking system for a DTC eCommerce brand using CheckoutChamp, Facebook Ads, Google Sheets, and Zapier.

Objective

Produce daily profit visibility and inventory health metrics that remain accurate even when data sources are imperfect or change over time.

Approach (data engineering first)

I treated this like a small data pipeline: ingest, normalize, QA, then model.

  • API ingestion in Zapier with pagination, normalization, looping, and upsert/dedup logic.
  • Fixed missing “New Sale” orders by switching source-of-truth from Order Details to Transaction Details API and re-ingesting history.
  • Built a multi-tab spreadsheet engine: Orders, OrderItems, Daily Data Log, Perf_Daily, Inv_Status, Cost_History, Data Quality Checks.
  • Implemented FIFO-style depletion + time-based costing to preserve historical accuracy across cost changes.

Deliverables

Dashboards plus the “engine” underneath.

  • Performance dashboard with Yesterday vs Last 30 Days toggle.
  • Inventory health metrics: units/day, reorder-by date, days left, stock value, shipped weight.
  • Data quality checks that flag missing dates/mismatches instead of failing silently.
  • Documentation of assumptions and edge cases.

Results

Dashboards aligned with real inputs after history correction; automations functional with QA checks to prevent silent gaps.

Reusable checklist

If you’re doing something similar, this is the short checklist I follow to keep the work clean and close-ready.

  • Make ingestion idempotent: always upsert/dedup so reruns don’t duplicate data.
  • Choose the right source-of-truth endpoint and validate with reconciliation checks.
  • Track costs over time (Cost_History) so historical profit doesn’t get rewritten.
  • Build QA checks early—spreadsheets fail silently without them.
