E-commerce Company | Profit Intelligence Project

One operating view of profit, stock and data quality

Orders, revenue, cost, ad spend, inventory, refunds and reconciliation checks in one reporting system.

Context

A DTC ecommerce reporting system built in Google Sheets

Order, transaction, advertising and inventory data came from different sources and needed one operating structure.

My role

My role in the work

  • Workbook architecture and operating logic
  • CheckoutChamp and Facebook Ads ingestion patterns
  • Pagination, looping, normalisation and upsert/deduplication logic
  • Inventory depletion and time-based costing logic
  • Data-quality checks and dashboard-ready metrics

The control point

A missing sale exposed the wrong source rule

I traced the pattern to a source and parameter mismatch, changed the source of truth from the Order Details API to the Transaction Details API, then reprocessed the affected history.

What I changed

What I changed

  • Created structured Orders, Order Items, Daily Data, Performance, Inventory, Cost History and Data Quality views
  • Added missing-date, duplicate-order, product-mapping and revenue-mismatch checks
  • Built profit, margin, CPA, AOV, inventory-health and reorder calculations
  • Designed FIFO-style stock depletion and time-based costing

What this demonstrates

Operational reporting with controls built in

The system combined dashboard metrics with checks for missing dates, duplicate orders, product mapping issues and revenue mismatches.
